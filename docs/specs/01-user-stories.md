# 01. 기능 명세 및 사용자 스토리

> 상태: 초안(v1) — 2026-07-23, 2026-07-23 갱신(MVP 범위 결정 변경 반영 — Spotify+YouTube 동시 MVP, 세션 도중 서비스 전환, 서비스별 플레이리스트 독립 보존), 2026-07-23 추가(크로스플랫폼 혼합 모드 MVP 포함 결정 반영 — 세션 유형 세 번째 옵션, 매칭 확인 UI 신규 스토리, `09-cross-platform-mixed-mode.md` "결정 갱신" 절 참고), 2026-07-24 추가(세션 정원/3단계 권한 체계(방장·관리자·일반사용자)/Free 계정 처리 신규 스토리 — US-106, US-207~US-210. 상세 정책은 `04-playlist.md` "세션 정원"/"권한 체계"/"Free 계정 처리" 절 참고)
> 우선순위 표기: `[MVP]` 1차 범위, `[P2]` 2차 이후. 근거는 `06-mvp-scope-and-tech-stack.md` 참고.

## 배경

리더로부터 전달된 요구사항(계정 연동, 세션, 협업 플레이리스트, 저지연 동기화, Spotify/YouTube 지원)을 실행 가능한 단위의 기능 명세와 사용자 스토리로 분해한다. 에픽은 다음 6개로 구성한다.

1. 계정/서비스 연동
2. 세션(방) 생성·참여·관리
3. 협업 플레이리스트
4. 재생 동기화(재생 제어)
5. 참여자 간 소통(보조 기능)
6. 알림/온보딩

## 요구사항 — 에픽별 사용자 스토리

### 에픽 1. 계정/서비스 연동 `[MVP]`

- US-101 `[MVP]` 사용자로서, 나는 Spotify 계정으로 로그인(OAuth)하여 내 계정의 Premium 상태를 앱이 확인할 수 있게 하고 싶다.
- US-102 `[MVP]` 사용자로서, 내가 Spotify Premium이 아니면 앱이 이를 안내하고 재생 제어 기능을 제한하길 원한다 (동기화 재생은 Premium 전용).
- US-103 `[MVP]` (2026-07-23 P2→MVP 승격) 사용자로서, 나는 YouTube/Google 계정으로 로그인하여 YouTube Premium 여부와 무관하게 서비스를 이용하고 싶다 (단, 광고 노출 여부는 계정 상태와 무관하게 서드파티 임베드 환경 제약을 받을 수 있고, MVP는 이 광고 노출 가능성을 감수하는 것으로 사용자가 결정함 — `03-youtube-integration.md` 3절·7절·8절, `06-mvp-scope-and-tech-stack.md` "갱신된 MVP 범위 결정" 참고).
- US-104 `[MVP]` 사용자로서, 나는 앱 내에서 언제든 연동된 음악 서비스 계정을 로그아웃/재연동할 수 있길 원한다.
- US-105 `[MVP]` 사용자로서, 방을 만들 때 이 방이 "Spotify 방"인지 "YouTube 방"인지 선택하고 싶다 (한 세션은 한 번에 하나의 서비스로만 재생되는 것을 기본 정책으로 유지 — 이유는 `05-sync-architecture.md` 참고. 단, 이 선택이 세션 생성 이후 영구 고정은 아님 — US-105b 참고).
- US-105b `[MVP]` (2026-07-23 신규, 2026-07-24 갱신) 참여자로서(주로 방장), 세션 도중에도 세션 설정 화면에서 현재 사용 중인 서비스를 Spotify ↔ YouTube로 전환하고 싶다. 전환 시 재생 중이던 곡은 멈추고, 전환된 서비스의 플레이리스트로 화면/재생이 바뀐다. (한 세션이 두 서비스를 동시에 재생하는 것은 여전히 금지된다 — "혼용 금지"가 아니라 "한 번에 하나만, 언제든 전환 가능"으로 정책이 구체화됨.) **(2026-07-24 갱신) 이 전환 권한의 주체는 방장·관리자로 제한된다** — 일반사용자는 서비스 전환을 실행할 수 없다. 상세는 US-208, `04-playlist.md` "권한 체계" 절 참고.
- US-105c `[MVP]` (2026-07-23 신규) 참여자로서, 세션에서 서비스를 전환해도 전환 전에 사용하던 서비스 쪽 플레이리스트(추가해둔 곡, 순서, 선곡자 정보)가 삭제되지 않고 그대로 보존되길 원한다. 나중에 다시 그 서비스로 돌아오면 이전 상태 그대로 이어서 사용할 수 있어야 한다 (개념적으로 세션 1개 : 서비스별 플레이리스트 N개 — 상세는 `06-mvp-scope-and-tech-stack.md`, `04-playlist.md` 참고).
- US-105d `[MVP]` (2026-07-23 신규, 크로스플랫폼 혼합 모드 MVP 포함 결정 반영) 사용자로서, 방을 만들 때 "Spotify 방"/"YouTube 방" 외에 **"혼합(Mixed) 방"**을 세 번째 옵션으로 선택하고 싶다. 혼합 방에서는 참여자마다 각자 자신이 로그인한 플랫폼(Spotify 또는 YouTube)으로 참여할 수 있다(멜론/지니뮤직은 `08-korean-services-melon-genie.md` 결론에 따라 여전히 참여 불가 — 실질적으로 Spotify 참여자와 YouTube 참여자의 공존을 의미함). 혼합 방은 US-105b(세션 도중 서비스 전환)의 대상이 아니다 — 애초에 여러 서비스가 동시에 활성 상태이므로 "전환"할 대상이 없다(상세는 `09-cross-platform-mixed-mode.md` "결정 갱신 (2026-07-23)" 절 참고).
- US-106 `[MVP]` (2026-07-24 신규) 사용자로서, 내가 Free 계정(무료 등급)이면 곡 재생(동기화 재생 참여)이 불가능하다는 안내를 명확하고 이해하기 쉽게 받고 싶다. (Free 계정 사용자가 세션 참여 자체는 가능한지, 플레이리스트 편집만 가능하고 재생만 제한되는지는 아직 **확인 필요** — 상세는 `04-playlist.md` "Free 계정(무료 등급) 처리" 절 참고. 실질적으로는 Spotify Free 계정에 한정될 가능성이 높다는 제안도 같은 절 참고, YouTube는 US-103에 따라 Premium 여부와 무관하게 이용 가능한 별개 정책.)

### 에픽 2. 세션(방) 생성·참여·관리 `[MVP]`

- US-201 `[MVP]` 사용자로서, 방을 생성하고 초대 코드/링크를 받아 상대에게 공유하고 싶다.
- US-202 `[MVP]` 사용자로서, 초대 코드/딥링크를 받으면 앱을 열어 바로 방에 참여하고 싶다.
- US-203 `[MVP]` 방장으로서, 방 참여자 목록과 각자의 연결 상태(정상/지연/끊김)를 보고 싶다.
- US-204 `[MVP]` 사용자로서, 방장이 자리를 비워도(앱 종료·연결 끊김) 세션이 유지되고, 필요 시 다른 참여자가 방장 권한을 이어받길 원한다 (호스트 마이그레이션).
- US-205 `[P2]` (2026-07-24 참고: 최대 인원 부분은 아래 US-207로 구체화되어 MVP로 승격됨. 공개-비공개 설정 부분은 여전히 P2로 남음) 사용자로서, 방에 최대 인원 제한/공개-비공개 설정을 지정하고 싶다.
- US-206 `[MVP]` 사용자로서, 네트워크가 불안정해져도 자동 재접속되어 세션에서 이탈하지 않길 원한다.
- US-207 `[MVP]` (2026-07-24 신규, 기존 US-205의 최대 인원 부분을 구체화·MVP 승격) 방장으로서, 세션 생성 시 최대 인원(정원)을 **12명 이하** 범위에서 직접 설정하고 싶다(세션 정원의 절대 상한은 12명). 상세는 `04-playlist.md` "세션 정원" 절 참고.
- US-208 `[MVP]` (2026-07-24 신규) 방장/관리자로서, 나는 세션 도중 서비스를 전환(Spotify↔YouTube, US-105b)할 수 있는 권한을 갖고 싶다. 일반사용자는 이 권한을 갖지 않는다. 방장은 다른 참여자를 관리자로 임명해 이 권한을 위임할 수 있다(임명 세부 방식은 `04-playlist.md` "권한 체계" 절의 "확인 필요" 항목 참고, 확정되지 않음).
- US-209 `[MVP]` (2026-07-24 신규) 일반사용자로서, 나는 서비스 전환 권한이 없어도 곡 추가/삭제/순서변경(US-301~303)은 기존과 동일하게 자유롭게 할 수 있길 원한다 — 3단계 권한 체계가 협업 플레이리스트 편집 권한을 축소하지 않는다는 점을 명확히 하는 스토리다.
- US-210 `[MVP]` (2026-07-24 신규) 참여자로서, 세션 화면에서 각 참여자의 역할(방장/관리자/일반사용자)을 배지 등으로 구분해 보고 싶다.

### 에픽 3. 협업 플레이리스트 `[MVP]`

- US-301 `[MVP]` 참여자로서, 곡을 검색해 현재 방의 플레이리스트에 추가하고 싶다.
- US-302 `[MVP]` 참여자로서, 플레이리스트의 아무 곡이나 삭제할 수 있길 원한다 (권한 제한 여부는 방 설정에 따름, 기본은 전원 허용).
- US-303 `[MVP]` 참여자로서, 드래그 등으로 플레이리스트 순서를 바꿀 수 있고, 이 변경이 즉시 다른 참여자에게도 반영되길 원한다.
- US-304 `[MVP]` 참여자로서, 각 곡 옆에 "누가 추가했는지"(닉네임/프로필) 표시를 보고 싶다.
- US-305 `[MVP]` 참여자로서, 다음 곡이 자동으로 이어 재생되길 원한다 (플레이리스트 끝까지 순차 재생).
- US-306 `[P2]` 참여자로서, "좋아요"나 "다음 곡으로 건너뛰기 투표" 같은 협업 상호작용을 하고 싶다.
- US-307 `[P2]` 참여자로서, 이전에 사용한 방의 플레이리스트를 저장해 다시 불러오고 싶다.
- US-308 `[MVP]` (2026-07-23 신규) 참여자로서, 한 세션 안에서 Spotify 플레이리스트와 YouTube 플레이리스트가 서로 독립적으로 유지되길 원한다 — 어느 한쪽에 곡을 추가/삭제/순서변경 해도 다른 쪽 플레이리스트에는 영향이 없어야 한다 (US-105b/US-105c와 동일 정책의 플레이리스트 관점 서술, 상세는 `04-playlist.md` 참고).
- US-309 `[MVP]` (2026-07-23 신규, 혼합 모드) 참여자로서, 혼합 방에서 곡이 내 플랫폼에 자동으로 매칭됐을 때, 그 매칭 결과(제목/아티스트/썸네일/길이와 일치율 또는 신뢰도 등급, 예: "이 곡을 YouTube에서 찾았어요 (일치율 92%)")를 명확히 확인하고 싶다.
- US-310 `[MVP]` (2026-07-23 신규, 혼합 모드) 참여자로서, 자동 매칭 결과가 틀렸다고 판단되면 내가 직접 내 플랫폼에서 곡을 재검색해 원하는 트랙으로 수동 교체하고 싶다. 자동 매칭 결과를 확인 없이 그대로 재생에 들어가는 일은 없어야 한다(상세 요구사항은 `09-cross-platform-mixed-mode.md` "결정 2" 절 참고).

### 에픽 4. 재생 동기화(재생 제어) `[MVP]`

- US-401 `[MVP]` 참여자로서, 누군가 재생/일시정지/곡 넘기기를 하면 다른 참여자 화면에도 즉시(가능한 최소 지연) 반영되길 원한다.
- US-402 `[MVP]` 참여자로서, 내가 방에 늦게 들어와도 현재 재생 중인 곡과 정확한 재생 위치로 자동으로 맞춰지길(late join sync) 원한다.
- US-403 `[MVP]` 참여자로서, 내 재생이 다른 참여자보다 어긋났을 때(드리프트) 앱이 자동으로 보정(미세 탐색/속도 조절)해주길 원한다.
- US-404 `[MVP]` 참여자로서, 현재 동기화 상태(정상/지연 n초/재동기화 중)를 화면에서 확인하고 싶다.
- US-405 `[P2]` 방장으로서, 재생 제어 권한을 "방장만" 또는 "전원 허용"으로 설정하고 싶다. (2026-07-24 참고: 이 스토리는 재생 조작(재생/일시정지/seek) 권한에 대한 것으로, US-208의 "서비스 전환" 권한과는 별개의 축이다 — 혼동 주의.)
- US-406 `[MVP]` 참여자로서, Spotify 방에서는 내 Spotify 앱이, YouTube 방에서는 앱 내장 플레이어가 실제 오디오를 재생하는 방식임을 이해할 수 있는 안내를 받고 싶다 (완전한 서버 스트리밍이 아님을 사용자에게 투명하게 알림).

### 에픽 5. 참여자 간 소통 (보조 기능) `[P2]`

- US-501 `[P2]` 참여자로서, 방 안에서 텍스트 채팅이나 짧은 리액션(이모지)을 보내고 싶다.
- US-502 `[P2]` 참여자로서, 곡이 바뀔 때 누가 다음 곡을 골랐는지 알림을 받고 싶다.

### 에픽 6. 알림/온보딩 `[MVP 최소 범위]`

- US-601 `[MVP]` 신규 사용자로서, 앱 최초 실행 시 Spotify/YouTube 중 사용할 서비스와 계정 연동을 안내받고 싶다.
- US-602 `[MVP]` 사용자로서, 상대방이 초대했을 때 푸시 알림으로 알고 싶다.
- US-603 `[P2]` 사용자로서, 상대가 방에 입장/퇴장했을 때 알림을 받고 싶다.

## 제약/리스크

- US-406은 제품 신뢰도에 중요하다. "우리 서버가 음악을 스트리밍해준다"는 오해를 주면 안 된다 — 실제로는 각자 기기의 로컬 플레이어(Spotify 앱 또는 내장 YouTube 플레이어)가 재생하고, 우리는 "동시에 같은 지점을 재생하도록 조율"하는 역할이다. 이 기대치 설정 실패는 리뷰/평판 리스크로 이어질 수 있다.
- US-105(한 세션 내 서비스 혼용 금지, 한 번에 하나만 재생)은 여전히 유지되는 정책 제안이다. 한 세션에서 Spotify와 YouTube를 동시에 재생하면 동기화 기준 시계를 어느 플레이어에 맞출지 애매해지고, 각 서비스의 오차 특성이 달라 최약체 기준으로 전체 경험이 저하된다. (2026-07-23 갱신: 다만 "생성 시 선택 후 영구 고정"은 더 이상 정책이 아니다 — US-105b로 세션 도중 전환이 MVP 범위로 추가됐다. "동시 재생 금지"와 "전환 가능"은 서로 다른 축이며 둘 다 동시에 성립한다.) 추후 사용자 피드백에 따라 재검토 가능.
- US-105b/US-105c/US-308(서비스 전환·플레이리스트 독립 보존)은 데이터 모델에 "세션 1 : 서비스별 플레이리스트 N(현재 N=2)" 구조를 요구한다. 전환 순간 재생이 끊기고 재동기화가 필요하다는 점, 비활성 서비스 쪽 플레이리스트는 동기화 대상에서만 빠지고 데이터는 유지되어야 한다는 점을 구현 단계에서 유의해야 한다 (`06-mvp-scope-and-tech-stack.md` "갱신된 MVP 범위 결정" 절 참고).
- US-401~404(동기화 실시간성)의 실제 달성 가능한 수치는 서비스별 제약에 크게 좌우된다 — 상세는 `02`, `03`, `05` 문서 참고. 구체적인 목표 오차값(예: ±300ms)은 구현/검증 단계에서 프로토타입으로 검증 후 확정할 것을 제안한다 (기획 단계에서 근거 없이 숫자를 확정하지 않음).
- US-105d/US-309/US-310(혼합 모드)은 YouTube가 ISRC 등 업계 표준 곡 식별자를 노출하지 않아 매칭이 원천적으로 휴리스틱(제목 유사도 + 아티스트 일치 + 길이 오차)에 의존한다는 근본적 한계를 안고 있다(`09-cross-platform-mixed-mode.md` 1·2절). 이 리스크는 "매칭 결과 고지 + 사용자 확인/수정 UI"로 완화될 뿐 완전히 제거되지는 않는다는 점을 구현/디자인/검증 단계 모두 인지해야 한다. 매칭 신뢰도 점수 산출 알고리즘의 구체 가중치·임계값은 실측 스파이크 이후 확정을 제안한다(근거 없이 확정하지 않음).
- (2026-07-24 신규) US-208/US-210(3단계 권한 체계)은 관리자 임명 방식·인원 상한·호스트 마이그레이션 시 권한 승계 규칙이 아직 **확인 필요** 상태로 남아 있다(`04-playlist.md` "권한 체계" 절 참고) — 구현 착수 전 리더/사용자와 재확인이 필요하다. 서버(향후 확정될 Firebase Cloud Functions 등) 측에서 권한 검증을 강제해야 하며, 클라이언트 UI에서 버튼을 숨기는 것만으로는 우회를 막을 수 없다는 점도 유의해야 한다.
- (2026-07-24 신규) US-106(Free 계정 처리)은 "Free 계정 사용자가 세션 참여 자체는 가능한지"가 기존 "전원 Premium 필요" 전제(US-101/US-102)와 상충 소지가 있어 **확인 필요**로 남아 있다(`04-playlist.md` "Free 계정(무료 등급) 처리" 절 참고). 기획 에이전트는 "참여는 허용하되 재생만 제한"하는 해석을 우선 제안했으나 최종 확정은 사용자/리더 몫이다.

- (2026-07-24 추가) 세션 정원(US-207)·3단계 권한 체계(US-208~US-210)·Free 계정 처리(US-106)는 사용자가 이번에 확정한 신규 MVP 요구사항으로, 위 제안 범위(에픽 1·2·3·4·6)에 각각 편입된다. 다만 관리자 임명 방식 등 세부 규칙은 여전히 확인 필요 상태이므로, 이 부분이 확정되지 않은 채로도 구현에 착수할 수 있도록 "임명 UI 슬롯은 마련하되 세부 정책은 설정값으로 분리"하는 등의 유연한 설계를 구현 단계에 제안한다.
