# 01. 기능 명세 및 사용자 스토리

> 상태: 초안(v1) — 2026-07-23
> 우선순위 표기: `[MVP]` 1차 범위, `[P2]` 2차 이후. 근거는 `06-mvp-scope-and-tech-stack.md` 참고.

## 배경

리더로부터 전달된 요구사항(계정 연동, 세션, 협업 플레이리스트, 저지연 동기화, Spotify/YouTube 지원)을 실행 가능한 단위의 기능 명세와 사용자 스토리로 분해한다. 에픽은 다음 6개로 구성한다.

1. 계정/서비스 연동
2. 세션(방) 생성·참여·관리
3. 협업 플레이리스트
4. 재생 동기화(재생 제어)
5. 참여자 간 소통(보조 기능)
6. 알림/온보딩

## 요구사항 — 에픽별 사용자 스토리

### 에픽 1. 계정/서비스 연동 `[MVP]`

- US-101 `[MVP]` 사용자로서, 나는 Spotify 계정으로 로그인(OAuth)하여 내 계정의 Premium 상태를 앱이 확인할 수 있게 하고 싶다.
- US-102 `[MVP]` 사용자로서, 내가 Spotify Premium이 아니면 앱이 이를 안내하고 재생 제어 기능을 제한하길 원한다 (동기화 재생은 Premium 전용).
- US-103 `[P2]` 사용자로서, 나는 YouTube/Google 계정으로 로그인하여 YouTube Premium 여부와 무관하게 서비스를 이용하고 싶다 (단, 광고 노출 여부는 계정 상태와 무관하게 서드파티 임베드 환경 제약을 받을 수 있음 — `03-youtube-integration.md` 참고).
- US-104 `[MVP]` 사용자로서, 나는 앱 내에서 언제든 연동된 음악 서비스 계정을 로그아웃/재연동할 수 있길 원한다.
- US-105 `[MVP]` 사용자로서, 방을 만들 때 이 방이 "Spotify 방"인지 "YouTube 방"인지 선택하고 싶다 (한 방 안에서 서비스를 혼용하지 않는 것을 기본 정책으로 제안 — 이유는 `05-sync-architecture.md` 참고).

### 에픽 2. 세션(방) 생성·참여·관리 `[MVP]`

- US-201 `[MVP]` 사용자로서, 방을 생성하고 초대 코드/링크를 받아 상대에게 공유하고 싶다.
- US-202 `[MVP]` 사용자로서, 초대 코드/딥링크를 받으면 앱을 열어 바로 방에 참여하고 싶다.
- US-203 `[MVP]` 방장으로서, 방 참여자 목록과 각자의 연결 상태(정상/지연/끊김)를 보고 싶다.
- US-204 `[MVP]` 사용자로서, 방장이 자리를 비워도(앱 종료·연결 끊김) 세션이 유지되고, 필요 시 다른 참여자가 방장 권한을 이어받길 원한다 (호스트 마이그레이션).
- US-205 `[P2]` 사용자로서, 방에 최대 인원 제한/공개-비공개 설정을 지정하고 싶다.
- US-206 `[MVP]` 사용자로서, 네트워크가 불안정해져도 자동 재접속되어 세션에서 이탈하지 않길 원한다.

### 에픽 3. 협업 플레이리스트 `[MVP]`

- US-301 `[MVP]` 참여자로서, 곡을 검색해 현재 방의 플레이리스트에 추가하고 싶다.
- US-302 `[MVP]` 참여자로서, 플레이리스트의 아무 곡이나 삭제할 수 있길 원한다 (권한 제한 여부는 방 설정에 따름, 기본은 전원 허용).
- US-303 `[MVP]` 참여자로서, 드래그 등으로 플레이리스트 순서를 바꿀 수 있고, 이 변경이 즉시 다른 참여자에게도 반영되길 원한다.
- US-304 `[MVP]` 참여자로서, 각 곡 옆에 "누가 추가했는지"(닉네임/프로필) 표시를 보고 싶다.
- US-305 `[MVP]` 참여자로서, 다음 곡이 자동으로 이어 재생되길 원한다 (플레이리스트 끝까지 순차 재생).
- US-306 `[P2]` 참여자로서, "좋아요"나 "다음 곡으로 건너뛰기 투표" 같은 협업 상호작용을 하고 싶다.
- US-307 `[P2]` 참여자로서, 이전에 사용한 방의 플레이리스트를 저장해 다시 불러오고 싶다.

### 에픽 4. 재생 동기화(재생 제어) `[MVP]`

- US-401 `[MVP]` 참여자로서, 누군가 재생/일시정지/곡 넘기기를 하면 다른 참여자 화면에도 즉시(가능한 최소 지연) 반영되길 원한다.
- US-402 `[MVP]` 참여자로서, 내가 방에 늦게 들어와도 현재 재생 중인 곡과 정확한 재생 위치로 자동으로 맞춰지길(late join sync) 원한다.
- US-403 `[MVP]` 참여자로서, 내 재생이 다른 참여자보다 어긋났을 때(드리프트) 앱이 자동으로 보정(미세 탐색/속도 조절)해주길 원한다.
- US-404 `[MVP]` 참여자로서, 현재 동기화 상태(정상/지연 n초/재동기화 중)를 화면에서 확인하고 싶다.
- US-405 `[P2]` 방장으로서, 재생 제어 권한을 "방장만" 또는 "전원 허용"으로 설정하고 싶다.
- US-406 `[MVP]` 참여자로서, Spotify 방에서는 내 Spotify 앱이, YouTube 방에서는 앱 내장 플레이어가 실제 오디오를 재생하는 방식임을 이해할 수 있는 안내를 받고 싶다 (완전한 서버 스트리밍이 아님을 사용자에게 투명하게 알림).

### 에픽 5. 참여자 간 소통 (보조 기능) `[P2]`

- US-501 `[P2]` 참여자로서, 방 안에서 텍스트 채팅이나 짧은 리액션(이모지)을 보내고 싶다.
- US-502 `[P2]` 참여자로서, 곡이 바뀔 때 누가 다음 곡을 골랐는지 알림을 받고 싶다.

### 에픽 6. 알림/온보딩 `[MVP 최소 범위]`

- US-601 `[MVP]` 신규 사용자로서, 앱 최초 실행 시 Spotify/YouTube 중 사용할 서비스와 계정 연동을 안내받고 싶다.
- US-602 `[MVP]` 사용자로서, 상대방이 초대했을 때 푸시 알림으로 알고 싶다.
- US-603 `[P2]` 사용자로서, 상대가 방에 입장/퇴장했을 때 알림을 받고 싶다.

## 제약/리스크

- US-406은 제품 신뢰도에 중요하다. "우리 서버가 음악을 스트리밍해준다"는 오해를 주면 안 된다 — 실제로는 각자 기기의 로컬 플레이어(Spotify 앱 또는 내장 YouTube 플레이어)가 재생하고, 우리는 "동시에 같은 지점을 재생하도록 조율"하는 역할이다. 이 기대치 설정 실패는 리뷰/평판 리스크로 이어질 수 있다.
- US-105(서비스 혼용 금지)은 임시 정책 제안이다. 한 방에 Spotify 사용자와 YouTube 사용자가 섞이면 동기화 기준 시계를 어느 플레이어에 맞출지 애매해지고, 각 서비스의 오차 특성이 달라 최약체 기준으로 전체 경험이 저하된다. 추후 사용자 피드백에 따라 재검토 가능.
- US-401~404(동기화 실시간성)의 실제 달성 가능한 수치는 서비스별 제약에 크게 좌우된다 — 상세는 `02`, `03`, `05` 문서 참고. 구체적인 목표 오차값(예: ±300ms)은 구현/검증 단계에서 프로토타입으로 검증 후 확정할 것을 제안한다 (기획 단계에서 근거 없이 숫자를 확정하지 않음).

## 제안

- MVP는 에픽 1(Spotify만)·2·3·4(핵심)·6(최소)로 한정하고, 에픽 5와 YouTube 지원(에픽 1의 US-103)은 2차 단계로 미루는 것을 권고한다. 근거는 `06-mvp-scope-and-tech-stack.md`의 리스크 비교 참고.
- 재생 권한 모델(US-405)은 MVP에서는 "전원 허용" 단일 모드로 단순화하고, 세부 권한 관리는 P2로 미루는 것을 제안한다.
