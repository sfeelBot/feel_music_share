# 08. 멜론(Melon)·지니뮤직(Genie Music) 서드파티 연동 가능성 조사

> 상태: 초안(v1) — 2026-07-23
> 리서치 근거: Melon 공식 이용약관 페이지, Genie Music 이용약관(WebSearch 요약 경유, 원문 페이지 직접 대조는 실패 — 아래 명시), SK플래닛 개발자센터(현재 폐쇄) 관련 보도/GitHub 이슈, 각 서비스의 비공식 서드파티 라이브러리 저장소 (2026-07-23 기준 WebSearch/WebFetch로 확인)
> 이 문서는 `07-alternative-services.md`와 동일한 조사 기준(공식 API/SDK 존재 여부 → 재생 제어 가능 여부 → 유료 구독 요건 → ToS 허용 여부)을 멜론·지니뮤직에 적용한 결과다. 07 문서의 비교표에도 요약 행을 추가했다.

## 배경

리더로부터 멜론·지니뮤직이 서드파티 재생 동기화 앱(이 프로젝트)에 연동 가능한지 조사 요청을 받았다. 두 서비스 모두 국내 음원 스트리밍 시장에서 메인스트림 카탈로그(가요/K-POP 등)를 폭넓게 보유하고 있어, "우리가 지원하는 서비스에 국내 이용자가 실제로 쓰는 서비스가 없다"는 제품 공백을 메울 수 있는지가 조사의 동기다.

조사 기준은 07 문서와 동일하게 다음 순서로 확인한다.

1. 서드파티 앱을 위한 **공식 개발자 API/SDK**가 존재하는가 (검색, 재생 제어, 인증 각각)
2. 존재한다면: 재생 제어(원격 재생/일시정지/탐색)가 가능한가, 참여자 전원 유료 구독이 필요한가, ToS상 우리 같은 다중 사용자 동기화 재생 앱에서의 사용이 허용되는가
3. 존재하지 않는다면: 비공식적으로라도 연동할 방법이 있는가, 아니면 완전히 배제해야 하는가

## 요구사항 (조사 목표)

- 멜론/지니뮤직 각각에 대해 위 기준으로 결론을 낸다.
- 결론은 `09-cross-platform-mixed-mode.md`(크로스플랫폼 혼합 모드)에서 "이 두 서비스가 혼합 모드에 참여할 수 있는가"를 판단하는 전제 조건으로 재사용된다.

## 조사 결과

### 1) 멜론(Melon)

**공식 개발자 API/SDK: 과거에는 존재했으나 현재는 폐쇄됨.**

- SK플래닛이 2012년경부터 `developers.skplanetx.com`을 통해 "멜론 음악 정보 검색 API"(제목/앨범명/아티스트명 검색 등)를 서드파티에 공개한 적이 있다(API 스토어에 등록 이력 확인: `apistore.co.kr/generalApi/generalApiView.do?general_service_seq=22`). 다만 이는 **검색/메타데이터 조회용**이었고, 재생 제어(원격 재생/일시정지/탐색)를 제공하는 API였다는 근거는 찾지 못했다(확인 필요 — 서비스 자체가 종료되어 원문 API 명세를 더 이상 확인할 수 없음).
- **2018년 4월 3일부로 SK플래닛 개발자센터(Open API 포털) 전체가 서비스를 종료했다** — "제공 중인 API들의 사업자 변경, 서비스 이관 등 제반 환경 변화로 효율적 운영을 위해 종료"한다는 공지가 확인된다(확실성: 높음, 다수의 국내 IT 언론 보도로 교차 확인. 다만 원 공지 페이지 자체는 사이트 폐쇄로 직접 열람 불가 — 언론 보도 인용에 의존, `developers.skplanetx.com` 자체가 현재 DNS 조회 실패로 접속 불가함을 직접 확인함).
- 2026년 현재, 멜론이 공식적으로 운영하는 서드파티용 개발자 포털/API/SDK는 **발견하지 못했다**. 카카오 개발자 커뮤니티(`devtalk.kakao.com`)에도 "멜론 API 문의드립니다" 류의 글이 여러 건 올라와 있는 것으로 보아, 일반 개발자들도 공식 경로를 찾지 못해 커뮤니티에 문의하는 상황으로 추정된다(정황 증거).
- 재생 제어·OAuth 로그인을 제공하는 공식 SDK는 존재하지 않는다.

**이용약관(ToS) — 원문 직접 확인, 확실성 높음**

멜론 플레이어 이용약관(`info.melon.com/terms/web/terms2.html?termsType=TYPE02`) 제6조 3항 원문:

> "이 약관상의 소프트웨어에서 제공되는 모든 서비스 및 컨텐츠의 사용은 이용자 본인만의 비상업적인 용도로만 가능합니다. 이용자는 회사가 멜론을 통하여 제공하는 소프트웨어, 정보 및 서비스를 수정 또는 복사, 제작, 양도, 판매할 수 없습니다."

- 이는 Spotify/YouTube의 "personal, non-commercial use" 조항과 본질적으로 동일한 구조다 — 콘텐츠를 제3자 앱에서 재가공/재전송하는 것은 이 조항이 금지하는 "수정·복사·양도" 범주에 해당할 가능성이 매우 높다.
- 제8조 2항의 "그리드 딜리버리" 관련 조항(저장된 음원 데이터의 일부를 다른 이용자에게 전송하는 기능)도 확인했으나, 이는 멜론 서비스 자체가 제공하는 제한적 기능(회사 서비스 내에서만 허용)에 관한 것이지, 서드파티 앱이 자체 재생/동기화 기능을 만들 권리를 부여하는 조항이 아니다.
- 유료서비스약관(`info.melon.com/terms/web/terms1_2.html`)에도 "다운로드 받은 음악콘텐츠를 사적 이용 범위 내에서 사용해야 하고 영리 목적 영업장 등에서 재생할 수 없다", "음악감상서비스를 녹음하거나 다운로드 받은 콘텐츠를 불법 유포·공유해서는 안 된다"는 조항이 확인된다.

**결론**: 멜론은 (1) 현재 서드파티가 이용할 수 있는 공식 검색/재생제어/인증 API·SDK가 전혀 없고, (2) 설령 있었다 해도 이용약관이 콘텐츠의 제3자 앱 재사용/재전송을 명시적으로 금지하고 있어, 우리 앱과 같은 다중 사용자 동기화 재생 서비스에서의 사용은 **기술적으로 불가능하고 정책적으로도 금지된다.**

### 2) 지니뮤직(Genie Music)

**공식 개발자 API/SDK: 발견하지 못했다.**

- 지니뮤직(KT 자회사)이 운영하는 공개 개발자 포털, API 문서, SDK를 검색했으나 **일반에 공개된 공식 서드파티 개발자 API는 확인되지 않았다.**
- 대신 발견되는 것은 전부 **비공식(unofficial) 서드파티 라이브러리**다. 예: `GenieAPI`(GitHub, Pma10) — 실시간 차트/검색 결과/가사 추출 등을 제공한다고 소개하나, 공식 API 호출이 아니라 **웹 스크레이핑 방식**으로 동작하는 것으로 확인된다. `korea-music-chart-api` 류의 여러 프로젝트도 지니뮤직을 포함한 국내 음원 차트를 스크레이핑으로 수집한다.
- 이런 비공식 라이브러리는 (a) 지니뮤직이 승인/문서화한 것이 아니라 리버스 엔지니어링이며, (b) 지니뮤직 웹/앱 구조가 바뀌면 언제든 깨질 수 있고, (c) 재생 제어(원격 재생/탐색)를 제공하지 않는다(대부분 차트·검색·가사 조회 수준). 재생 제어까지 지원하는 비공식 라이브러리는 발견하지 못했다.
- 지니뮤직 고객센터(`help@ktmusic.co.kr`) 등 제휴 문의 채널은 존재하나, 이는 정식 파트너십/제휴 협의를 거쳐야 하는 영업 절차이지 개발자가 셀프서비스로 즉시 발급받아 쓸 수 있는 API 키 체계가 아닌 것으로 보인다(확인 필요 — 실제 제휴 시 어떤 API가 제공되는지는 지니뮤직에 직접 문의해야 확인 가능).

**이용약관(ToS) — 원문 페이지 직접 대조는 실패, WebSearch 요약 경유(확실성: 중간)**

- 지니뮤직 공식 이용약관 페이지(`genie.co.kr` 산하 URL 다수 시도) 접속을 여러 차례 시도했으나 모두 404 또는 접근 실패로, **원문 전체를 직접 대조하지 못했다.** 아래 인용은 검색 엔진 요약을 경유한 것이며, 정확한 조항 번호는 확인하지 못했다(확실성: 중간, 향후 실채택 검토 시 원문 재대조 필요).
- 요약된 내용: "회사가 제공하는 정보를 회사의 사전 동의 없이 복제 또는 유통시키거나 상업적으로 이용할 수 없다", "법령·계약에 따라 전송할 권리가 없는 내용을 게시·업로드·이메일 발송·기타 방법으로 전송하거나 공개할 수 없다", "회사 또는 제3자의 저작권 등 지식재산권을 침해하는 행위는 회원 자격 박탈 사유"라는 취지의 조항이 있는 것으로 확인된다.
- 이는 멜론·Spotify·YouTube와 동일한 패턴("개인적·비상업적 이용만 허용, 재배포·재전송 금지")으로 보이며, 우리 앱처럼 여러 사용자가 지니뮤직 콘텐츠를 동기화 재생하는 구조는 이 조항 취지에 저촉될 가능성이 높다고 판단한다(다만 확실성은 중간 등급 — 원문 재확인 권고).

**결론**: 지니뮤직도 (1) 서드파티용 공식 API/SDK가 없고(비공식 스크레이핑 라이브러리만 존재), (2) 이용약관도 재배포·상업적 이용을 금지하는 것으로 보이는 취지의 조항이 확인되어, 멜론과 동일하게 **현재로서는 연동이 불가능하다.**

## 제약/리스크

1. **공식 채널 부재**: 두 서비스 모두 검색·재생 제어·인증(로그인) 중 어느 하나도 서드파티에게 공식적으로 열려 있지 않다. Spotify/YouTube 조사(`02`, `03` 문서)에서는 최소한 "기술적으로는 가능하지만 제약이 있다"는 수준이었던 반면, 멜론/지니는 **애초에 시작점(공식 API) 자체가 없다.**
2. **비공식 스크레이핑 채택 시 리스크**:
   - ToS 위반 소지가 명확하다(위 인용 조항).
   - 서비스 구조 변경 시 예고 없이 깨질 수 있어 상용 서비스의 안정적 기반으로 삼기 부적합하다.
   - 로그인(인증)까지 비공식으로 처리하려면 사용자의 계정 자격증명(아이디/비밀번호)을 우리 서버/앱이 직접 다루는 안티패턴이 강제되는데, 이는 OAuth 기반의 Spotify/YouTube와 근본적으로 다른 보안 리스크이며 사용자 신뢰 문제로 직결된다.
   - 국내법(저작권법, 컴퓨터프로그램보호법, 정보통신망법상 크롤링/접근 관련 조항 등) 저촉 가능성도 배제할 수 없다 — 이는 법률 자문이 필요한 영역이며 이 문서 조사 범위를 넘는다(**확인 필요**).
3. **정식 제휴 경로의 불확실성**: 두 회사 모두 제휴 문의 채널은 존재하나, 실제로 서드파티 동기화 재생 앱에 필요한 수준(재생 제어 API, OAuth)의 파트너십을 체결해줄지, 조건이 무엇인지(비용, 심사, 독점 조항 등)는 전혀 알려진 바가 없다. 이는 개발이 아니라 사업/법무 협상의 영역이다.

## 제안

1. **결론(권고): 멜론·지니뮤직은 MVP는 물론 현재 시점의 로드맵에서 완전히 배제할 것을 권고한다.** Spotify/YouTube처럼 "제약을 감수하고 채택"하는 선택지가 아니라, 채택 자체를 논할 기술적 기반이 없는 상태이기 때문이다.
2. 만약 사용자가 국내 서비스 지원을 여전히 강하게 원한다면, 유일하게 남는 현실적 경로는 **각 회사(카카오엔터테인먼트/멜론, KT/지니뮤직)에 공식 파트너십을 직접 제안·협의하는 것**뿐이다(멜론: `melon_info@kakaoent.com`, `1566-7727`, 지니뮤직: `help@ktmusic.co.kr`). 이는 개발자가 셀프서비스로 진행할 수 있는 일이 아니라 사업 협상이므로, 진행 여부와 우선순위는 전적으로 사용자(및 리더)의 결정 사항으로 남긴다. 기획 에이전트로서는 이 협상의 성사 가능성이나 조건을 예측할 근거가 없다.
3. `09-cross-platform-mixed-mode.md`에서 검토하는 크로스플랫폼 혼합 모드에 멜론/지니뮤직이 참여하는 시나리오는, 이 결론에 따라 **현재는 성립 불가**로 처리한다(해당 문서에서 재확인).
4. `07-alternative-services.md`의 비교표에 이 조사 결과를 요약한 행을 추가했다(아래 참고).
