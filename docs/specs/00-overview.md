# 00. 프로젝트 개요 (feel_music_share)

> 상태: 초안(v1) — 2026-07-23 작성
> 작성: 기획 서브에이전트
> 이 문서는 `docs/specs/` 전체 문서의 인덱스 겸 최상위 개요다.

## 배경

장거리 연인·친구는 물리적으로 떨어져 있어도 "같은 음악을 같은 순간에 듣는 경험"을 통해 정서적 유대감을 느끼고 싶어 한다. 기존에는 통화를 켜놓고 각자 음악 앱을 수동으로 맞춰 재생하는 식의 불편한 방법을 쓰거나, Spotify Jam(그룹 세션)·Discord 화면공유 등 파편적인 대안에 의존해왔다.

feel_music_share는 이 문제를 앱 하나로 해결한다:
- 여러 명이 하나의 "방(세션)"에 모여 공동 플레이리스트를 관리하고,
- 동일한 곡을 최대한 낮은 지연·오차로 동기화하여 함께 듣는다.

사용자가 이미 쓰고 있는 음악 서비스(Spotify 또는 YouTube/YouTube Music)를 그대로 활용해야 하므로, 신규 음원 라이선싱이나 자체 스트리밍 인프라 없이 **각 서비스의 공식 연동 수단 안에서** 기능을 구현하는 것이 원칙이다.

## 요구사항 (제품 목표 요약)

1. **세션/방**: 사용자가 방을 만들고 초대 링크/코드로 다른 사용자를 초대해 함께 듣는다.
2. **동시 재생 동기화**: 방 참여자 전원이 동일한 곡을 최대한 같은 재생 위치(타임스탬프)에서 듣는다. 재생/일시정지/탐색(seek)/스킵 조작이 실시간으로 전원에게 반영된다.
3. **협업 플레이리스트**: 참여자 누구나 곡 추가·삭제·순서 변경 가능. 각 곡 옆에 "누가 추가했는지" 표시.
4. **멀티 음악 서비스 지원**: Spotify와 YouTube(Premium) 두 서비스를 지원한다. 단, 두 서비스는 기술적 제약이 크게 다르므로 지원 수준(1차/2차)을 구분한다 — 상세 근거는 `02-spotify-integration.md`, `03-youtube-integration.md` 참고.
5. **모바일 우선**: iOS/Android 네이티브(또는 크로스플랫폼) 앱.

### 비기능 요구사항

| 항목 | 목표 |
|---|---|
| 재생 동기화 오차 | 최우선 지표. 체감상 "어긋남"을 느끼지 않는 수준을 목표로 하되, 서비스별 제약상 물리적 하한선이 다름 (상세는 `05-sync-architecture.md`) |
| 가용성 | 방장(호스트) 이탈 시에도 세션이 끊기지 않아야 함 (재호스트/마이그레이션) |
| 계정 요건 | Spotify 이용 시 참여자 전원 Premium 필요. YouTube 이용 시에도 광고 없는 경험을 원하면 참여자 전원 YouTube Premium 필요 (단, 서드파티 앱에서 이 광고 제거가 보장되는지는 `03-youtube-integration.md`에서 별도 검증 — 결론적으로 "확인 필요/리스크 있음") |
| 플랫폼 | iOS, Android 동시 지원 |

## 제약/리스크 (요약 — 상세는 각 하위 문서)

- Spotify와 YouTube는 "서드파티 앱이 재생을 원격 제어할 수 있는가"의 기술적 성숙도가 다르다. Spotify는 공식 App Remote SDK로 앱 자체(iOS/Android)에서 제어 가능하지만, YouTube는 서드파티의 프리미엄(무광고) 재생을 공식적으로 보장하는 API가 없다.
- 두 서비스 모두 "우리 서버가 오디오를 직접 스트리밍"하는 구조가 아니라, **각 참여자의 기기에서 로컬로 재생되는 각자의 플레이어를, 우리 앱이 명령을 보내 동기화**하는 구조로 귀결된다 (상세는 `05-sync-architecture.md`). 즉 완벽한 프레임 단위 동기화가 아니라 "체감상 맞는" 수준을 목표로 잡아야 한다.
- Spotify는 참여자 전원이 Premium이어야 재생 제어(on-demand 재생)가 가능하다.
- 기술 스택은 이 문서에서 후보만 제시하며 최종 결정은 사용자 몫이다 (`06-mvp-scope-and-tech-stack.md`).
