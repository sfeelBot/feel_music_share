# 07. Spotify/YouTube 대안 음악 서비스 조사 — "참여자 전원 무료 + 정식 곡 재생" 가능한 서비스가 있는가

> 상태: 초안(v1) — 2026-07-23
> 이 문서는 리더 보고 및 사용자 의사결정을 위한 조사 문서다. 결론은 기획 에이전트의 조사 결과일 뿐 최종 서비스 채택 결정은 사용자 몫이다.

## 배경

`02-spotify-integration.md`, `03-youtube-integration.md`는 각각 Spotify(전원 Premium 필수)와 YouTube(Premium 무광고 여부 자체가 불확실, ToS상 우회 재생/중계 모델은 명시적으로 금지)를 조사했다. 두 서비스 모두 "참여자 전원이 무료로(유료 구독 없이) 정식 곡을 함께 듣는다"는 조건을 만족하지 못한다.

이번 조사는 리더의 요청에 따라 Spotify/YouTube를 제외한 다른 음악 스트리밍 서비스/API 중에 다음 4가지 조건을 모두 만족하는 것이 실제로 있는지 확인하는 것이 목적이다.

1. **전곡 스트리밍이 참여자 전원에게 무료**인가 (미리듣기 30초 등이 아니라)
2. 공식 API/SDK로 **원격 재생 제어**(재생/일시정지/탐색)가 가능한가
3. **메인스트림 상업 음악** 카탈로그를 포함하는가 (인디/CC 음악처럼 카탈로그가 제한적이지 않은가)
4. ToS상 **다중 사용자 동기화 재생 용도의 서드파티 앱**이 허용되는가

## 상세 분석

### 1) 무료 + 재생 제어를 만족하는 후보(Audius, Jamendo, FMA/ccMixter)의 공통 한계 — 카탈로그

Audius와 Jamendo는 "참여자 전원 무료, 공식 API로 재생 제어 가능"이라는 두 조건은 명확히 만족한다. 그러나 둘 다 구조적으로 **메인스트림 상업 음악을 다루지 않는다**:

- Jamendo/FMA/ccMixter는 애초에 "CC 라이선스를 받은 음원만" 다루는 것이 서비스의 정체성이다. 메이저/인디 레이블이 정식 발매한 상업 음원(사용자가 실제로 듣고 싶어할 히트곡)은 여기 없다 — 있을 수가 없다. CC 라이선스 음원과 상업 음원은 라이선스 체계 자체가 다르기 때문이다.
- Audius는 카탈로그 규모가 100만 곡 이상으로 상대적으로 크지만, 이는 스포티파이(1억 곡 이상, 메이저/인디 레이블 정식 계약 포함)와는 성격이 다른 "탈중앙 플랫폼에 직접 업로드하는 아티스트 풀"이다. 인기 아티스트의 정식 음원이 여기 있을 가능성은 낮다.

이 프로젝트의 핵심 가치가 "같이 듣고 싶은 곡을 같이 듣는 것"이므로, 카탈로그가 사용자가 실제로 원하는 곡을 담고 있지 않다면 앱의 존재 이유 자체가 무너진다. 즉 이 후보들은 "기술적으로 되지만 제품으로서 의미가 없는" 경우다.

### 2) 메인스트림 카탈로그 + 재생 제어를 만족하는 후보(Deezer, Tidal, Apple Music)의 공통 한계 — 유료 구독

Deezer/Tidal/Apple Music은 모두 메이저 레이블과 정식 라이선스 계약을 맺어 카탈로그가 풍부하고 공식 SDK도 있다. 그러나 셋 다 예외 없이 **"전곡 재생은 최종 사용자의 유료 구독을 전제로 한다"**는 동일한 구조를 갖는다.

- Deezer: API 문서 자체가 "무료 API 접근 등급과 무관하게, 전곡 스트리밍은 최종 사용자가 Deezer 유료 구독자여야 한다"고 명시.
- Tidal: 개발자 포털에 "Full-length Playback은 TIDAL 구독자만 접근 가능하며, 비구독자는 30초까지만 접근 가능"이라고 명시.
- Apple Music: MusicKit 자체가 "사용자 본인의 Apple Music 구독"을 전제로 설계되어, 구독이 없으면 API 사용 자체가 불가능(개발자 평가판 면제조차 없음).

즉 Spotify와 완전히 동일한 패턴이다 — 이는 우연이 아니라 **업계 표준 구조**다(아래 3번 참고).

### 3) SoundCloud — 가장 애매한 중간 지점

SoundCloud는 유일하게 "무료 사용자도 전곡을 들을 수 있는" 메이저 상업 음악 서비스처럼 보이지만, 자세히 보면 두 가지 문제가 있다.

- **카탈로그 문제**: SoundCloud는 원래 인디/DJ/리믹스/데모 음원 중심 플랫폼이다. 메이저 레이블과 라이선스 계약(Warner, Sony 등)을 맺었지만, 그 콘텐츠 상당수는 `SoundCloud Go+`(유료) 전용이거나, 아티스트가 "앱 재생(third-party API playback)"을 개별적으로 차단할 수 있는 권한을 갖고 있다. 즉 인기곡일수록 API로 못 가져올 가능성이 커진다 — 실제로 "API 기반 음악 발견 서비스들이 결국 인디 밴드에만 작동하는 서비스가 됐다"는 개발자 커뮤니티의 관찰이 다수 존재한다.
- **ToS 문제**: SoundCloud API 이용약관은 "여러 사용자의 User Content를 집계해 온디맨드 리스닝 서비스로 만드는 행위" 및 "다른 서비스의 콘텐츠와 결합해 스트리밍하는 재생 경험"을 만드는 것을 금지한다. 우리 앱은 여러 사용자가 선곡한 SoundCloud 트랙을 모아 자체 UI/세션에서 동기화 재생하는 구조이므로, 이 조항에 저촉될 가능성을 배제할 수 없다(다만 이 조항의 1차 목적은 "SoundCloud를 대체하는 경쟁 서비스"를 막는 데 있어 보이며, 우리처럼 재생을 SoundCloud의 공식 Widget iframe에 위임하는 방식이라면 위반이 아니라고 해석될 여지도 있다 — 법률 자문 없이는 확정할 수 없는 회색지대).
- 접근성 문제: 2026년 5월부터 SoundCloud가 "Self-serve API key"를 Artist-Pro 구독자에게만 제공하기 시작한 정황이 있어, 일반 서드파티 개발자의 신규 앱 등록 자체가 예전보다 더 제한적으로 바뀌고 있을 가능성이 있다(승인제 유지, 정확한 현재 정책은 공식 문의로 재확인 필요).

### 4) 그 외 조사했으나 후보에서 제외한 서비스

- **Amazon Music**: Web API가 여전히 비공개(closed) 베타 상태로, 일반 서드파티 개발자는 신청 자체가 불가능하다. 논의 대상이 되지 못함.
- **Napster/Rhapsody**: 2026년 1월, 스트리밍 서비스 자체를 종료하고 AI 사업으로 피벗했다는 보도가 확인됨. 더 이상 존재하지 않는 서비스라 논외.
- **Bandcamp**: 서드파티 대상 공개 스트리밍 API가 2015년경 이미 폐쇄되었고, 현재 API는 레이블/머천다이즈 정산 파트너 전용이다. 재생 제어를 논할 대상 자체가 없음.
- **멜론/지니뮤직**: `(2026-07-23 추가)` 리더의 별도 조사 요청으로 국내 서비스 두 곳을 추가 조사했다. 둘 다 서드파티용 공식 검색/재생제어/인증 API·SDK가 전혀 없어(멜론은 과거 있었던 검색 API조차 2018년 종료) 이 표의 다른 서비스들과 달리 "제약이 있지만 시도는 가능한" 수준이 아니라 애초에 논의할 기술적 기반이 없다. 상세 근거(이용약관 원문 인용 포함)는 `08-korean-services-melon-genie.md`에 별도 정리했다.

## 제약/리스크 — 왜 구조적으로 "전원 무료 + 메인스트림 곡"이 존재하기 어려운가

조사 결과, **"참여자 전원 무료 + 정식 곡(메인스트림 상업 카탈로그) + 공식 API로 재생 제어 가능"이라는 세 조건을 모두 만족하는 서비스는 발견되지 않았다.** 이는 우연이 아니라 아래와 같은 구조적 이유 때문으로 판단된다.

1. **메이저 레이블 라이선스는 무료가 아니다.** Spotify Free/SoundCloud Free 같은 "광고 지원 무료 온디맨드 스트리밍"이 존재하기는 하지만, 이는 레이블에 지급되는 로열티를 광고 수익으로 충당하는 구조다. 이 광고 수익 배분과 재생 집계(스트림 카운트 등)는 플랫폼이 자사 앱/웹에서 직접 통제할 때만 성립한다 — 서드파티 앱에 그 재생을 위임하면 광고 노출·재생 집계를 플랫폼이 보장할 수 없으므로, 대부분의 서비스는 "무료 등급의 전곡 재생을 서드파티 API로 노출"하는 것 자체를 아예 막아버린다(Deezer/Tidal처럼 API 문서에 명문화하거나, Apple Music처럼 애초에 무료 등급 자체가 없거나).
2. **API로 전곡을 노출하는 순간, 저작권 콘텐츠의 무단 재배포/캐싱 위험이 커진다.** 그래서 이들 서비스는 "구독자 인증을 완료한 사용자에게만, 공식 SDK/임베드 플레이어를 통해서만" 전곡을 노출하는 방식으로 리스크를 좁힌다. 이 인증·통제 비용을 감당하려면 결국 구독료(또는 광고 직접 통제)가 필요하다.
3. **예외적으로 "전원 무료"가 되는 서비스(Audius, Jamendo, FMA)는 애초에 메이저 레이블 라이선스 비용 자체가 발생하지 않는 콘텐츠(CC 라이선스, 독립 아티스트 자발적 업로드)만 다루기 때문에 무료가 가능한 것**이다. 즉 "라이선스 비용이 없으니 무료로 열 수 있다"는 것이지, "무료이면서 동시에 메이저 상업 카탈로그를 갖는 방법을 찾아냈다"는 것이 아니다.
4. SoundCloud는 위 두 축의 정확히 중간에 있다 — "일부 무료 + 일부 상업 카탈로그"이지만, 정확히 그 중간 지점이기 때문에 "인기곡일수록 API로 못 가져온다"는 딜레마가 생긴다. 이는 예외가 아니라 위 구조적 논리를 그대로 보여주는 사례다.

결론적으로, **"참여자 전원 무료로 원하는 인기곡을 정식으로 함께 듣는다"는 요구사항 자체가, 현재 음악 산업의 라이선스/수익 구조상 어떤 스트리밍 서비스를 골라도 기술이 아니라 사업 모델 층위에서 막혀 있다.** 이는 Spotify/YouTube에 국한된 문제가 아니라 이 조사에서 다룬 모든 상업 음악 서비스에 공통되는 한계다.

## 제안 — 권고

이 조사 결과를 바탕으로 아래 선택지를 사용자에게 제시한다. 최종 결정은 사용자 몫이다.

1. **(권고 A) 기존 방향 유지**: `06-mvp-scope-and-tech-stack.md`의 기존 권고대로 Spotify(전원 Premium)를 MVP 축으로 채택한다. "전원 무료" 조건은 이번 조사로 사실상 불가능함이 확인되었으므로, "전원 유료 구독 + 정식 메인스트림 카탈로그 + 검증된 공식 SDK"라는 Spotify의 조합이 가장 현실적인 절충안이다.
2. **(권고 B) 카탈로그를 포기하고 완전 무료 서비스로 전환**: Audius 또는 Jamendo를 채택해 "참여자 전원 무료"를 달성하되, 사용자가 실제로 듣고 싶은 메인스트림 인기곡은 애초에 카탈로그에 없을 가능성이 높다는 점을 인지한 상태로 제품 방향을 바꾼다(예: "발견 중심 인디 음악 공유 앱"으로 컨셉 자체를 재정의). 이는 CLAUDE.md가 정의한 현재 제품 정체성("같이 듣고 싶은 곡을 같이 듣는다")과 상충되므로, 채택 시 제품 컨셉 재정의가 선행되어야 한다.
3. **(권고 C, 비권장) SoundCloud를 절충안으로 검토**: "일부 무료 + 부분적 상업 카탈로그"라는 중간 지점을 받아들이되, (a) 인기곡 상당수가 API로 재생 불가능할 수 있다는 점, (b) ToS상 "다중 사용자 온디맨드 집계 서비스" 금지 조항과의 충돌 가능성이 법률 자문 없이는 해소되지 않는다는 점 때문에, 제품의 핵심 가치를 안정적으로 보장하기 어렵다. 채택하려면 최소한 (i) 목표 사용자층이 실제로 듣는 곡들이 SoundCloud API로 재생 가능한지 표본 조사, (ii) ToS 저촉 여부에 대한 법률 자문을 선행 조건으로 제안한다.

**기획 에이전트 의견**: 권고 A(기존 Spotify 중심 방향 유지)가 가장 현실적이다. "전원 무료"라는 조건을 만족하는 유일한 방법은 카탈로그를 포기하는 것뿐이므로, 이는 기술 선택의 문제가 아니라 "제품이 무엇을 하는 앱인지"에 대한 근본적인 재정의 문제다. 이 재정의가 필요하다고 판단되면 리더를 통해 사용자와 먼저 논의할 것을 제안한다.
